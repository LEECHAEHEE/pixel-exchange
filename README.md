# 도트 객장 (pixel-exchange)

도트 그래픽으로 만든 온라인 증권 객장. 접속한 사람들이 캐릭터로 함께 돌아다니고, 의자에 앉아 전광판 시세를 보며 채팅한다.
서버는 Node.js + WebSocket, 화면은 빌드 도구·프레임워크 없는 정적 파일이다.

## 실행

```bash
npm install
npm start
```

브라우저에서 `http://localhost:5178/` 을 열고 닉네임을 입력해 입장한다(비우면 `손님1` 처럼 자동).
같은 네트워크의 다른 PC 는 `http://<이 PC 의 IP>:5178/` 로 들어온다. Windows 방화벽에서 5178 포트를 허용해야 할 수 있다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 5178 | 서버 포트 |
| `TOSS_CLIENT_ID` · `TOSS_CLIENT_SECRET` | 없음 | 토스증권 Open API 키. 있으면 국내 시가총액 상위 종목 실시세를 쓴다 |
| `TOSS_KEY_FILE` | 없음 | 위 두 값 대신 키 파일 경로(첫 줄 `tsck_…`, 둘째 줄 `tssk_…`). 저장소 밖에 둔다 |
| `TOSS_TOP` | 192 | 전광판에 올릴 시가총액 상위 종목 수 (전광판 최대 칸 수 12×16) |
| `TOSS_POLL_MS` | 2000 | 장 시간(평일 07:50~20:10) 현재가 조회 간격. 그 밖에는 1분 |
| `MARKET_WS_URL` | 없음 | 실제 시세 웹소켓 주소. 토스 키도 이것도 없으면 데모 시세 |
| `SUPABASE_URL` · `SUPABASE_SERVICE_KEY` | 없음 | 유저 기록(닉네임·접속·아이템·잔액)을 둘 Supabase 프로젝트 URL 과 service_role 키. 없으면 서버 메모리에만 둔다 |
| `SUPABASE_KEY_FILE` | 없음 | 위 두 값 대신 키 파일 경로(첫 줄 프로젝트 URL, 둘째 줄 service_role 키). 저장소 밖에 둔다 |
| `NEWS_OFF` | 없음 | `1` 이면 전광판 아래 띠의 경제 뉴스를 끈다 |
| `NEWS_COUNT` | 15 | 띠에 흘릴 최신 헤드라인 수 |
| `NEWS_POLL_MS` | 120000 | 뉴스 RSS 다시 읽는 간격(최소 1분) |
| `NEWS_MAX_AGE_H` | 12 | 이보다 오래된 기사는 띠에서 뺀다(시간) |
| `MARKET_API_KEY` | 없음 | 실제 시세 API 키. 코드에 쓰지 말고 여기로 넘긴다 |
| `RACE_CYCLE_SEC` | 300 | 경마 주기(초). 시험할 때 줄인다. 최소 150 |

### 토스증권 실시세

1. 토스증권 WTS > 설정 > Open API 에서 client_id·client_secret 을 발급받는다.
2. 같은 메뉴의 **허용 IP 관리** 에 서버를 돌릴 PC(또는 서버)의 공인 IP 를 등록한다. 없으면 403 으로 막히고 전광판 상태가 `허용 IP 미등록` 으로 뜬다.
3. 키 파일 경로를 넘겨 실행한다.

```bash
TOSS_KEY_FILE=../toss_key.txt npm start
```

종목 순서는 섹터 API 가 주는 시가총액(하루 1회 갱신) 내림차순이고, 등락은 일봉의 전일 종가 대비로 계산한다.
토큰은 키 하나당 1개만 유효하므로 같은 키로 서버를 두 군데서 동시에 돌리지 않는다.

### 경제 뉴스 띠

전광판 아래 흐르는 띠에 연합뉴스(마켓)·한국경제(증권)·매일경제(증권) RSS 최신 헤드라인을 `[출처 시각] 제목` 으로 흘린다.
전광판에 올라 있는 종목 이름(줄임말 포함)이 제목에 있는 기사를 종목당 하나씩 앞에 두고, 그다음 코스피·공매도·실적 같은
시장 키워드 기사를 둔다. 둘 다 아닌 기사(인사·일반 정책 등)는 뺀다. 줄임말·키워드는 `server/news.js` 의 `ALIASES`·`MARKET_KEYWORDS`.
본문·요약은 쓰지 않고 제목과 출처만 보여 준다. 피드 주소는 `server/news.js` 의 `FEEDS` 에서 바꾼다.
새 헤드라인은 띠가 한 바퀴 다 돈 뒤에 바뀌어 흐르던 글이 중간에 끊기지 않는다.

## 배포 (Render 무료 플랜)

저장소 루트의 `render.yaml` 로 Render 에 올린다. Render 대시보드에서 New → Web Service → 이 저장소 주소를 넣거나,
New → Blueprint 로 `render.yaml` 을 그대로 쓴다. 빌드는 `npm ci`, 실행은 `npm start`, 포트는 Render 가 `PORT` 로 넘겨 준다.

- 15분 동안 들어오는 요청·웹소켓 메시지가 없으면 서버가 잠들고, 다음 접속 때 약 1분 뒤 깨어난다.
  접속자가 가만히 있어도 깨어 있도록 화면이 4분마다 `ping` 을 보낸다.
- 잠들었다 깨거나 다시 배포되면 접속자·의자 상태(메모리)는 초기화되고, 접속자는 자동으로 재입장한다.

## 조작

| 동작 | 키 | 보조 |
|---|---|---|
| 조작 방법 | 기본 화면에서 Esc 로 열고 닫음(다른 창이 열려 있을 때 Esc 는 그 창만 닫음) | 채팅창 옆 `[Esc] 조작 방법` 클릭 |
| 이동 | ↑ ↓ ← → | WASD(풋살장에서는 S·D 가 패스·슛이라 방향키만), 바닥 클릭 |
| 앉기 | 빈 의자에 붙어서 그 의자를 바라보고 Space (노란 화살표가 뜨는 의자). 뒤·옆·앞 어느 쪽에서든 가능 | 없음 |
| 일어나기 | Space 또는 ↓ ← → (↑ 는 앉은 채 유지). 앉기 전 서 있던 자리로 돌아감 | 화면 아래 띠 클릭 |
| 채팅 | Enter → 입력 → Enter. Esc 는 취소 | 입력창 클릭 |
| 상점 | 오른쪽 상점 주인을 바라보고 Space → 구매한다 / 나간다 (↑↓ 고르고 Space·Enter) | 항목 클릭 |
| 장소 이동 | 객장 가운데 빨간 복도를 따라 아래 끝까지 가면 사거리. 사거리 아래 복도 끝은 경마장, 왼쪽 끝은 풋살장, 오른쪽 끝은 마피아존 | 바닥 클릭 |
| 풋살 | 풋살장에서 S 패스, D 를 누르고 있다 떼면 슛(오래 누를수록 세게). 공이 없을 때 S·D 는 태클 | 팀 고르기·START 는 버튼 클릭 |
| 인벤토리 | I 로 열고 닫음. ← → 분류 탭, ↑↓ 고르기, Space 착용/해제, Ctrl+← → 미리보기 캐릭터 돌리기. 한 탭에 최대 5개가 보이고 나머지는 스크롤 | 버튼 클릭 |
| 감정표현 | C 로 채팅 입력줄 자리에 방향키 판을 열고, ↑ 인사(고개를 숙이는 꾸벅 인사, 약 1.4초). 다른 방향은 준비 중. C·Esc 로 닫기 | 판의 버튼 클릭 |
| 채팅 기록 | M 으로 `닉네임 : 내용` 목록을 열고 닫음. 서버가 켜진 뒤의 최근 100건(서버 메모리, 서버를 끄면 사라짐). 입장 전 채팅도 보임 | 없음 |
| 화면 가리기 | X 로 화면 전체를 까맣게(`[화면 가리기]` 표시), 다시 X 로 원래대로. 입력칸에서 글자 칠 때는 동작 안 함 | 없음 |

경마장 광장 왼쪽 마굿간 칸 앞에서 ↑ 를 보고 Space 를 누르면 말을 훔쳐 탄다(칸 3개, 칸마다 한 마리).
탄 채로 어느 장소든 다니고 걸음보다 빠르다. 말은 옷과 따로 그리므로 아이템을 갈아입어도 그대로다.
탄 채로 마굿간 칸 앞에서 다시 Space 를 누르면 원래 칸에 돌려놓는다. 접속을 끊으면 말은 마굿간으로 돌아간다.

탄 채로 F 를 누르면 말이 앞발을 들어 앞을 찬다(어느 장소든, 1초에 한 번). 바라보는 쪽 바로 앞
(옆을 보면 앞 24px·위아래 8px, 위·아래를 보면 앞 18px·좌우 10px)에 서 있는 사람이 맞으면 8px 밀려나며 넘어져
약 1.8초 동안 누워 있다가 일어난다. 누워 있는 동안은 움직이지 못하고 다시 차이지도 않는다.
앉은 사람·말 탄 사람은 맞지 않는다. 맞았는지는 서버(`server/stable.js` `hoof`)가 위치로 정한다.

경마장 관리인(NPC, `server/stable.js`)은 경마장에 말 탄 사람이 있으면 잠깐 뒤 쫓아온다.
걸음보다 빠르고 말보다 느리다. 닿으면 말을 뺏어 마굿간에 돌려놓는다.
풋살장에는 말을 타고 들어갈 수 없어, 들어가는 순간 내리고 말은 마굿간으로 돌아간다.
경마장을 벗어나면(위 문으로 사거리로 나가면) 더 쫓지 못하고 자리로 돌아간다. 탄 채로 다시 들어오면 또 쫓는다.

앉으면 착석 시점으로 바뀐다. 전광판이 화면 높이의 약 90% 로 커지고, 아래 띠에 내 줄 의자 등받이와
같은 줄에 앉은 사람들의 뒤통수가 2배로 보인다. 크기는 `config.js` 의 `boardSeated`, `seatedStrip` 에서 바꾼다.

나와 전광판 사이에 있는 사람(앞줄에 앉은 사람, 앞쪽을 지나가는 사람)도 아래 띠에 내 줄 사람과 같은 높이·크기로 보이고,
그 사람이 채팅하면 머리 위에 말풍선이 뜬다. 원근 없이 내 줄 뒤로 지나가는 모양이라, 내 줄에 사람이 앉은 자리에서는 가려진다.
내 뒤에 있는 사람은 보이지 않는다.

## 장소

객장 → 사거리 → 경마장·풋살장·마피아존 순으로 이어진다. 장소를 옮기면 화면이 잠깐 어두워졌다 밝아진다.
객장과 코인 거래소처럼 옆으로 붙은 방은 어두워지는 대신 옛 게임처럼 화면이 옆으로 밀리며 넘어간다(0.7초, 출구의 `slide`).
밀리는 동안 전광판 같은 DOM 오버레이도 화면과 같이 밀리고, 캐릭터는 움직이지 않으며 말풍선은 잠깐 숨는다.
같은 장소에 있는 사람만 보이고, 말풍선도 같은 장소 사람 것만 보인다.

| 장소 | 시점 | 출구 |
|---|---|---|
| 객장 (`exchange`) | 뒤에서 본 시점 | 빨간 복도 아래 끝 → 사거리 위쪽, 오른쪽 끝(상점 주인 아래) → 코인 거래소 왼쪽 |
| 코인 거래소 (`coin`) | 객장과 같은 방 모양, 의자·카펫 없음. 코인 전광판(아직 시세 없음) | 왼쪽 끝 → 객장 오른쪽 |
| 사거리 (`crossroad`) | 위에서 내려다본 시점. 객장 빨간 복도가 이어지는 실내 복도 사거리 | 위 복도 → 객장, 아래 복도 → 경마장, 왼쪽 복도 끝(초록 문) → 풋살장, 오른쪽 복도 끝(분홍 문) → 마피아존 |
| 경마장 (`racetrack`) | 위에서 내려다본 시점 | 위쪽 출입문 → 사거리 아래 복도 |
| 마피아존 (`mafiazone`) | 위에서 내려다본 시점 | 왼쪽 통로 → 사거리 오른쪽 끝 |
| 풋살장 (`futsal`) | 위에서 내려다본 실내 풋살장. 위쪽 관중석·점수판, 아래쪽 양 팀 벤치 | 오른쪽 위 문 → 사거리 왼쪽 끝 |


새 장소는 `public/js/places.js` 에 `{ paint, walk, blocks, exits }` 로 추가한다.

- `walk`: 발 위치가 이 사각형들 중 하나 안에 있어야 설 수 있다
- `blocks`: 발 주변이 겹치면 막힌다
- `exits`: 발이 들어서면 `to` 장소의 `spawn` 으로 옮겨 간다

안내 글씨는 `config.js` 의 `labels` 에 넣는다. 서버 `room.js` 의 `MAPS` 에도 이름을 넣어야 한다.
장소에 `decorate(list, g, t)` 를 두면 사람과 같은 깊이 순서로 더 그릴 수 있고(경마장 말, 풋살 공),
`dress(who, look)` 를 두면 그 장소에서만 옷을 바꿔 그린다(풋살 팀 유니폼). `arrowsOnly: true` 면 WASD 로 걷지 않는다.

## 경마

| 항목 | 내용 |
|---|---|
| 일정 | 5분마다 시계 기준(:00, :05, :10 ...) 출발. 서버를 막 켰을 때 출발까지 1분이 안 남았으면 그 판은 건너뛴다 |
| 말 | 5마리. 기수 옷 색 1 흰 · 2 검 · 3 빨 · 4 파 · 5 노 |
| 투표 | 출발 전까지 경마장 안에서 숫자키 1~5 또는 가운데 전광판 클릭. 한 사람 한 표, 다시 하면 바뀐다. 나가면 표가 빠진다 |
| 경주 | 5바퀴, 약 90초. 결승 뒤 20초 동안 결과(우승마·적중 인원·내 적중 여부)를 보여 준 다음 투표가 열린다 |

투표 중에는 말들이 아래쪽 직선에 나란히 서서 기다리고, 출발하면 위쪽 체크무늬 선에서 시계 반대 방향으로 돈다.
전광판은 투표 중에 남은 시간·말별 표 수, 경주 중에 바퀴·순위, 끝나면 최종 순위를 보여 준다.

### 우승이 랜덤이면서 접전이 되도록

경주는 출발 순간 서버(`server/race.js`)가 끝까지 계산하고, 말별 위치를 0.25초 간격으로 모두에게 보낸다(약 13KB).
화면은 그 사이를 이어 그리기만 하므로 모두가 같은 경주를 본다. 투표는 출발 전에 닫혀서 결과를 미리 보내도 상관없다.

모든 말이 같은 규칙을 따르고 차이는 운에서만 나온다.

- 속도가 1~3초마다 평균 ±6% 안에서 오르내린다
- 뒤처진 말은 따라붙는 힘을 받고, 혼자 앞선 말은 살짝 힘이 빠진다. 무리가 흩어지지 않는다
- 마지막 바퀴에서 말마다 다른 시점·세기·길이로 막판 스퍼트. 너무 일찍 시작하면 결승 전에 힘이 빠진다

`npm run race:check` 로 경주 2만 번을 돌린 결과:

| 지표 | 값 |
|---|---|
| 우승 분포 | 말마다 19.9 ~ 20.2% |
| 1·2위 차 | 평균 0.32초, 0.2초 이내 사진판정 41% |
| 선두 교체 | 경주당 약 11회 |
| 막판 역전 | 61% (4바퀴째 선두가 우승 못 함) |

`stable: { stalls: [말 있음?], keeper }` 가 들어 있다.

## 풋살

사거리 왼쪽 끝 초록 문으로 들어가는 실내 풋살장. 마피아처럼 그 장소에 있는 사람끼리 팀을 모아 경기한다.
공은 서버(`server/futsal.js`)가 굴려 모두에게 같은 자리에 보이고, 사람 위치는 다른 장소처럼 각자 보낸 값을 쓴다.

| 항목 | 내용 |
|---|---|
| 팀 | 레드(왼쪽 골대를 지킴)·블루(오른쪽). 팀 고르기 판에서 `레드 참가`·`블루 참가`·`자동 배정`(적은 쪽)·`관전`. 팀당 5명까지 |
| 시작 | 팀에 든 사람이 START. 양 팀에 1명 이상이면 시작(1 대 1 가능, 인원이 달라도 됨). 3·2·1 카운트다운 동안 모두 킥오프 자리로 옮겨지고 선수는 움직일 수 없다 |
| 승리 | 5골 먼저. 경기 시간 6분(멈춘 시간 제외)이 끝나면 많이 넣은 팀, 같으면 골든골(다음 골을 넣은 팀) |
| 골 | 공 전체가 골대 입구(높이 36px)의 골라인을 넘으면 골. 2.5초 세리머니(배너·화면 번쩍임) 뒤 실점한 팀이 킥오프(1.5초 준비) |
| 결과 | 이긴 팀, 점수, 득점 순서(득점자·도움·자책골), MVP(골 2점·도움 1점)를 10초 보여 준 뒤 팀 고르기로. 팀은 그대로 남아 바로 다시 할 수 있다 |
| 나가기 | 풋살장을 나가거나 접속이 끊기면 팀에서 빠진다. 경기 중 한 팀이 비면 남은 팀의 기권승 |
| 관전 | 팀이 없는 사람은 공에 닿지 않는다. 경기 중(카운트다운·경기·골 세리머니)에는 아래쪽 벤치 줄로 옮겨지고 그 안에서만 움직인다. 벤치 줄 오른쪽 끝 관전석 출입문으로 사거리에 나갈 수 있다. 채팅은 평소처럼 된다. 경기 중에는 팀을 고르거나 바꿀 수 없다 |
| 말 | 말을 탄 사람은 팀에 들어갈 수 없다(마굿간에 돌려놓고 와야 함) |

| 동작 | 내용 |
|---|---|
| 드리블 | 공에 닿으면(7px) 발 앞에 붙어 따라온다. 바라보는 쪽 앞에 붙는다. 공을 가진 사람은 걸음이 90% 로 느려진다(`public/js/futsal.js` 의 `DRIBBLE_SPEED`) |
| 뺏기 | 상대 드리블 공에 닿으면 뺏는다. 주인이 바뀐 뒤 0.8초는 못 뺏고, 뺏긴 사람은 0.45초 동안 다시 못 잡는다 |
| 패스 S | 바라보는 쪽 ±65° 안의 같은 팀 사람 중 가깝고 정면에 있는 사람에게 자동 조준(걷는 사람은 조금 앞을 봄). 없으면 앞으로 중간 세기 |
| 슛 D | 누르는 동안 캐릭터 옆 게이지가 차고(0.9초에 가득) 떼면 찬다. 바라보는 방향에 상대 골대 쪽 보정을 더하고, 아주 세게 차면 조금 빗나간다. 골대 반대쪽을 보고 차면 보정 없이 걷어낸다 |
| 태클 | 공이 없을 때 S·D. 13px 안의 상대 공을 뺏는다(0.9초에 한 번) |
| 찬 직후 | 찬 사람은 0.3초 동안 공을 다시 못 잡는다. 아주 빠른 공(200px/s 넘음)은 누구 발에도 안 붙는다 |

조정할 만한 값은 `server/futsal.js` 맨 위에 모여 있다(`MATCH_MS`·`WIN_GOALS`·`TEAM_MAX`·`DUR`·마찰 `FRICTION`·`DECEL`,
닿는 거리 `GRAB_R`·`STEAL_R`·`TACKLE_R`, 패스·슛 세기 `PASS_*`·`SHOT_*`, 킥오프 대형 `SLOTS_*`). 경기장 선·골대 자리(`FIELD`·`GOAL`)와
드리블 자리(`dribbleOffset`)·마찰은 `public/js/places.js` 의 `FS`, `public/js/futsal.js` 와 맞춰야 한다. 시험할 때는 `FUTSAL_MATCH_SEC=30 npm start` 처럼 경기 시간을 줄인다.

공은 굴러가는 동안만 0.066초(약 15Hz)마다 풋살장을 보는 사람에게 보낸다. 위치와 함께 속도를 보내 화면이 그 사이를 마찰을 반영해 내다보고,
드리블 중에는 위치 대신 주인만 알려 화면이 주인 발 앞에 붙여 그린다.

## 멀티플레이

- 한 객장, 인원 제한 없음. 의자(42개)는 먼저 앉은 사람 것이고, 동시에 앉으려 하면 서버가 늦은 쪽을 되돌린다.
- 위치는 각자 0.1초마다 바뀌었을 때만 보내고, 서버는 0.1초마다 바뀐 사람만 장소별로 모아 **그 장소를 보는 사람에게만** 뿌린다.
  다른 사람 캐릭터는 그 사이를 걷는 속도로 채워 끊기지 않게 보인다.
- 강아지·시세도 객장을 보는 사람에게만 보낸다. 탭을 숨기거나 X 로 가리면(`idle`) 위치·강아지·시세를 받지 않는다.
  장소에 들어오거나 다시 볼 때 서버가 `sync` 로 그 장소의 현재 모습을 한 번에 보낸다.
- 입장·퇴장·장소 이동·앉기/일어나기·착용·채팅·감정표현·경마는 드물어서 모두에게 보낸다(접속자 수와 다른 사람의 장소를 맞게 유지).
- 채팅은 서버를 거쳐 모두에게 전달된다. 말풍선은 5초 유지, 같은 사람이 다시 말하면 내용이 바뀐다. 0.3초에 한 번까지, 60자까지.
- 닉네임은 12자까지, 같은 닉네임도 허용한다. 로그인은 없다.

### 서버 메시지 (JSON, `t` 가 종류)

| 방향 | 종류 | 내용 |
|---|---|---|
| → 서버 | `join` | `{ name }` 입장 |
| → 서버 | `move` | `{ x, y, dir, moving }` |
| → 서버 | `sit` / `stand` | `{ seat }` / `{ x, y, dir }`. 앉기는 객장에서만 된다 |
| → 서버 | `go` | `{ map, x, y, dir }` 다른 장소로 옮김. 서버는 `sync` 로 답한다 |
| → 서버 | `idle` | `{ on: true \| false }` 탭을 숨기거나 X 로 가림 / 다시 봄. `false` 면 서버가 `sync` 로 답한다 |
| → 서버 | `chat` | `{ text }` |
| → 서버 | `equip` | `{ equip: [아이템 id] }` 착용 변경. `join` 에도 `equip` 을 함께 보낸다 |

| → 서버 | `emote` | `{ emote: 'bow' }` 감정표현. 서버는 정해진 종류만, 0.5초에 한 번까지 받는다 |
| ← 서버 | `emote` | `{ id, emote }` 다른 사람 감정표현 |
| ← 서버 | `dog` | `{ map, x, y, dir, moving, owner }` 강아지 상태(바뀌었을 때만, 0.2초에 한 번까지). 강아지가 있는 장소를 보는 사람에게만(장소를 옮긴 순간에는 떠난 장소에도). `welcome`·`sync` 에도 `dog` 가 들어 있다 |
| ← 서버 | `welcome` | 내 정보, 이미 있는 사람들, 시세 스냅샷 |
| ← 서버 | `join` / `leave` | 다른 사람 입장·퇴장 |
| ← 서버 | `moves` | `[[id, x, y, dir, moving, face?], ...]` 묶음. 같은 장소를 보는 사람에게만. 풋살장에서는 바라보는 8방향 `face` 도 붙는다(`move` 의 `f`) |
| ← 서버 | `sync` | `{ map, people: [[id, x, y, dir, moving, seat], ...], dog?, market? }` 장소에 들어오거나 다시 볼 때 그 장소의 현재 모습(나 제외)과 `dog`(강아지). 객장이면 `market`(시세 스냅샷)도 |
| ← 서버 | `sit` / `stand` / `sitDenied` | 의자 점유 변화, 내 앉기 거절 |
| ← 서버 | `go` | `{ id, map, x, y, dir }` 다른 사람이 장소를 옮김 |
| ← 서버 | `chat` | `{ id, text }` |
| ← 서버 | `symbols` / `ticks` / `indices` / `ticker` / `status` | 시세 |

시세 메시지(`symbols`·`ticks`·`indices`·`ticker`·`status`)는 객장을 보는 사람에게만 간다. 스냅샷(`welcome.market`·`sync.market`)은
`{ symbols, ticks, indices, ticker, status }` 이다. 데모 시세는 객장을 보는 사람이 없으면 쉰다.

## 상점

객장 오른쪽 끝(예전 화분 자리)에 상점 주인이 서 있다. 모든 접속자에게 같은 자리에 보이는 고정 NPC 다.
바라보고 Space 를 누르면 대화창이 열리고, `구매한다` 를 고르면 상점 창이 열린다.

| 분류 | 아이템 (61종, 100 ~ 5,000원) |
|---|---|
| 헤어 (15) | 기본 짧은머리, 스포츠머리, 가르마, 뾰족머리, 모히칸, 대머리, 뽀글 파마, 숏컷, 단발 보브, 긴 생머리, 웨이브 긴머리, 포니테일, 양갈래, 똥머리, 한쪽 땋은머리 |

아이템을 늘리려면 `public/js/items.js` 의 `ITEMS` 에 한 줄 추가한다. 색만 다른 아이템은 `wear` 의 색만 바꾸면 되고,
새 모양(무늬·뿔 등)은 `scene.js` 의 `drawPerson`·`drawHeadwear` 와 `items.js` 의 `ICONS` 에 그림을 더한다.

서버가 정하는 기본 외형은 머리 색과 기본 상의·하의뿐이다. 머리 모양·신발·모자는 처음 접속할 때 받는 기본 아이템
(기본 짧은머리·기본 신발, 절반은 기본 색 모자 하나)이라 인벤토리에서 벗을 수 있다. 모두 벗으면 민머리·맨발이 된다.

헤어는 모양만 바꾸고 머리 색은 사람마다 정해진 색을 그대로 쓴다. 모양은 `public/js/hairs.js` 에 앞·옆·뒤 도트 격자로 있고,
캐릭터·앉은 뒷모습·아이콘이 모두 이 격자로 그린다. 새 헤어는 격자를 하나 더하고 `items.js` 에 `hair(...)` 한 줄을 추가한다.
모자·왕관처럼 머리 꼭대기를 덮는 것을 쓰면 머리 위로 솟은 부분(뾰족 끝·모히칸·똥머리 등)은 눌려서 그리지 않는다.

상점 창에서는 ← → 분류, ↑ ↓ 아이템, Space·Enter 구매, Esc 닫기. 산 아이템은 인벤토리로 들어가고,
같은 아이템은 하나만 가질 수 있다(이미 있으면 "보유 중"). 처음 잔액은 10,000원이고, 서버가 잔액을 확인하고 깎는다.
돈을 버는 방법은 아직 없다.

## 강아지

흰 강아지가 한 마리 있다(처음에는 객장). 모든 접속자에게 같은 강아지가 보이도록 서버(`server/dog.js`)가 움직임·주인·있는 장소를 정한다.
나와 같은 장소에 있을 때만 화면에 보인다.

| 상황 | 동작 |
|---|---|
| 주인 없음 | 지금 장소의 통로를 오가며 돌아다니다 가끔 멈춘다(객장은 맨 앞·가운데 카펫 통로, 사거리는 두 복도, 경마장은 관람석 앞) |
| 같은 장소에서 누군가 강아지 근처(12px)로 들어옴 | 그 사람이 주인이 되고, 강아지가 주인 뒤를 따라간다. "멍!" 말풍선 |
| 다른 사람이 다가옴 | 그 사람이 새 주인. 단 주인이 바뀐 지 1초가 지나야 한다 |
| 주인이 다른 장소로 옮김 | 강아지도 주인 뒤로 함께 옮겨 간다 |
| 주인이 나감 | 그 장소에서 다시 혼자 돌아다닌다 |
| 주인이 10초 동안 가만히 있음(앉아 있는 것 포함) | 주인을 버리고 그 장소에서 바로 돌아다니기 시작한다 |
| 10초 넘게 가만히 있는 사람 | 강아지가 옆을 지나가도 주인이 되지 않는다. 움직여서 다가가면 다시 주인이 된다 |

근처에 계속 서 있는 것만으로는 주인이 바뀌지 않고, 멀리 있다가 **들어오는 순간**에만 바뀐다.
그래서 주인과 나란히 선 사람이 있어도 1초마다 주인이 오가지 않는다. 주인을 따라갈 때는 의자 사이로도 지나간다(강아지라서).

## 인벤토리

I 로 연다. 왼쪽에 내 캐릭터 미리보기(착용 모습, ◀ ▶ 또는 Ctrl+← → 로 방향 돌리기)와 부위별 착용 목록,
오른쪽에 상점과 같은 분류 탭(보유 개수 표시)과 그 분류의 보유 아이템 목록이 있다. 목록은 한 번에 최대 5개만 보이고 나머지는 스크롤한다.

| 착용 | 캐릭터에 보이는 모습 |
|---|---|
| 모자 | 모자 색 |
| 상의 / 하의 | 윗옷 / 바지 색 |
| 한벌옷 | 원피스는 허리선·주름·밑단이 있는 A라인 치마, 정장·작업복·트레이닝복은 위아래 같은 색(넥타이·옆줄). 입으면 상의·하의가 벗겨지고, 상의·하의를 입으면 한벌옷이 벗겨진다 |
| 신발 | 신발 색 (슬리퍼는 발가락이 보임) |
| 귀걸이 / 반지 | 귀 아래 / 손끝의 보석(없으면 금속) 색 점 |

- 보유·착용 목록과 잔액은 **서버의 유저 기록**(`server/accounts.js`)에 있다. 사람은 브라우저 고유 번호(localStorage 의 uid)로 구분하므로,
  다른 PC·브라우저나 사이트 데이터를 지운 브라우저는 새 사람이 된다. 기록은 Supabase 의 `px_users` 테이블에 두고(`server/supabase.sql`),
  키가 없으면 서버 메모리에만 둔다(서버를 끄면 사라짐).
- 기록을 처음 만들 때만 그 브라우저에 남아 있던 인벤토리를 옮겨 받는다. 그 뒤로는 구매(`buy`)·착용(`equip`)을 서버가 확인한다:
  잔액이 모자라거나 안 가진 아이템은 거절하고, 바뀐 인벤토리를 `inv` 로 알려 준다.
- 서버는 아이템 가격·부위를 `public/js/hairs.js`·`items.js` 를 그대로 읽어서 안다(`server/catalog.js`).
- 아이템 목록·아이콘·착용 규칙은 `public/js/items.js` 한 곳에 있다(상점·인벤토리·캐릭터 그림이 함께 씀).

## 전광판 구성

벽 양 끝까지 차지한다.

- 왼쪽 패널: 맨 위 전자시계(초 단위)·날짜·연결 상태, 그 아래 남은 높이를 KOSPI·KOSDAQ 이 반씩 나눠
  지수명 / 지수값 / 등락폭·등락률 / 거래량·거래대금 을 크게 보여준다
- 오른쪽: 종목 칸. **화면 크기에 따라 칸 수가 달라진다** (세로로 먼저 채움)
- 맨 아래: 뉴스/공지 흐르는 띠

종목 글자는 읽기 좋은 크기(12~16px) 안에서만 커지고, 남는 자리는 칸 수를 늘려 채운다.
창 크기를 바꾸면 다시 계산한다. 앉으면 글자를 1.35배 키운 뒤 같은 방식으로 칸을 나눈다.
칸에 다 못 들어간 종목도 마지막 시세를 기억해 두므로, 창을 키우면 바로 값이 채워진 채로 나타난다.
표시 순서는 `setSymbols` 로 넘긴 순서이고, 앞쪽 종목부터 보인다.

## 실제 시세 API 연동

서버가 증권사 API 에 **한 번만** 연결해 모든 접속자에게 나눠 준다. API 키는 서버에만 있고 브라우저로 가지 않는다.

`server/market.js` 의 `apiSource` 에서 두 함수만 채우면 된다. 재접속(지수 백오프)과 상태 표시는 이미 들어 있다.

```js
function subscribe(ws) {
  ws.send(JSON.stringify({ type: 'subscribe', key: apiKey, codes: ['005930', '000660'] }));
}

// 증권사 메시지를 { ticks?, indices?, ticker? } 로 바꾼다
function parse(data) {
  const m = JSON.parse(data);
  return { ticks: [{ code: m.code, price: m.price, change: m.diff, rate: m.rate }] };
}
```

그다음 환경변수로 켠다.

```bash
MARKET_WS_URL=wss://example/realtime MARKET_API_KEY=... npm start
```

공급원이 쓰는 메서드는 화면 전광판과 모양이 같다.

```js
market.setSymbols([{ code: '005930', name: '삼성전자' }, ...]);   // 표시 순서
market.push({ code: '005930', price: 71200, change: 800, rate: 1.14 });   // 배열도 가능
// volume(거래량)은 만주, amount(거래대금)는 억원 단위. 없으면 그 줄은 숨겨진다.
market.setIndices([{ name: 'KOSPI', value: 2650.12, change: 12.3, rate: 0.47, volume: 33856, amount: 49531 }]);
market.setTicker('하단에 흐를 뉴스/공지');
market.setStatus('LIVE', true);
```

REST 처럼 주기적으로 조회하는 API 라면 `setInterval` 안에서 조회해 위 메서드로 넣으면 된다.

## 렉 없이 돌게 한 장치

| 장치 | 효과 |
|---|---|
| 틱 합치기 | 서버는 0.2초, 화면은 한 프레임 단위로 같은 종목의 마지막 값만 반영 |
| 위치 묶어 보내기 | 0.1초마다 바뀐 사람만 장소별로 한 메시지로. 직렬화도 한 번만 |
| 보는 사람에게만 | 위치는 같은 장소, 강아지·시세는 객장을 보는 사람에게만. 숨긴 탭·가림 화면은 빼고 돌아오면 `sync` |
| 화면 파일 캐시 | 파일·gzip 본을 메모리에 두고 ETag 가 같으면 304 |
| 바뀐 글자만 쓰기 | 칸마다 이전 문자열을 기억해 같으면 건드리지 않음 |
| 깜빡임 일괄 해제 | 셀마다 타이머를 만들지 않고 100ms 주기 한 번에 정리 |
| 배경 미리 그리기 | 벽·바닥·전광판 틀은 시작 시 한 번만 그리고 매 프레임 이미지 한 장 붙이기 |
| 30fps 제한 | 도트 화면에 60fps 는 불필요, 탭이 숨겨지면 자동 정지 |
| CSS `contain` / transform | 전광판 변경이 페이지 전체 레이아웃을 다시 계산하지 않음, 말풍선·뉴스 띠는 transform 으로만 이동 |
